# Setu Platform — 30 / 60 / 90-Day Engineering Plan

## First 30 Days: Emergency Remediation & Core Stabilization

### Week 1: Eliminate Critical Vulnerabilities & Unbreak CI

- **P0 Fix:** Remove `/var/run/docker.sock` mount from `docker-compose.yml`.
- **CI Restoration:** Create `eslint.config.js` for ESLint 9; format codebase with `npm run format`; remove non-existent `dashboard` from `.github/workflows/ci.yml`.
- **Database Integrity:** Add migration `007_principal_unique_constraints.sql` to block duplicate principal registrations.
- **Client SDK:** Fix `packages/sdk` endpoint paths to `/v1/collections/:name/records` and add unit tests.

### Weeks 2–4: Performance & Operational Hardening

- **Gateway CPU Optimization:** Implement SHA-256 API key verification or in-memory LRU key caching, boosting gateway capacity from 20 RPS to >2,000 RPS.
- **Connection Pooling:** Introduce PgBouncer in Docker Compose and deployment manifests.
- **Gateway Timeouts:** Wrap all upstream HTTP proxies with 5s `AbortSignal` timeouts.
- **Repository Hygiene:** Purge obsolete `.semgrep/guardian.yml`, dead `__tests__/.gitkeep` files, and align `README.md` with real implementations.

---

## 31–60 Days: Structural Modernization & Concurrency Architecture

### Month 2: Service Consolidation & Async Audit

- **Service Consolidation (ADR-0004):** Consolidate 9 microservices into a Modular Monolith. Mount services as Fastify domain plugins, replacing internal HTTP hops and HMAC serialization with zero-overhead in-process routing.
- **Async Audit Worker (ADR-0001 Refinement):** Replace the synchronous `pg_advisory_xact_lock` in `setu_append_audit` with asynchronous queueing. Buffer audit events in PostgreSQL `audit_queue` and process them in micro-batches (every 100ms), restoring full horizontal concurrency.
- **S3 / MinIO Integration:** Replace the local `.storage` filesystem store with true S3/MinIO streaming uploads and presigned URL downloads.

---

## 61–90 Days: Enterprise Hardening, Observability & Scale

### Month 3: Sandboxing, Observability & Compliance

- **Sandboxed Functions Runtime (ADR-0003):** Implement V8 isolate or WebAssembly sandbox for `services/functions`.
- **Production Observability:** Instrument the modular monolith with OpenTelemetry and Prometheus `/metrics`. Deploy Grafana dashboards for RPS, P99 latency, DB pool utilization, and consent denials.
- **Distributed Rate Limiting:** Replace in-memory token buckets with Redis sliding-window rate limiting.
- **Kubernetes Production Readiness:** Write complete Helm chart templates in `deploy/helm/setu/templates` and set up container image publishing to Google Artifact Registry.
